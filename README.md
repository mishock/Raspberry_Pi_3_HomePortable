# Raspberry Pi 3 — переносимый проект (Home Assistant + HomeKit Switch в Docker)

Целевая роль железа: **узел умного гаража** на отдельной Raspberry Pi 3 — релейный вывод (например ворота/свет по вашей электросхеме через Waveshare Relay Board), **HomeKit** для «Дом», **Home Assistant** для сценариев и панелей. Эта формулировка применима **к этому переносимому проекту**; конфиг основного **Switch** под Pi 5 в воркспейсе может оставаться нейтральным.

## Идея и смысл (для Cursor и продолжающего в новом чате)

Этот каталог — **единый архив под перенос на отдельную Raspberry Pi 3**, без жёстких абсолютных путей воркспейса **`Документы`**.

- **Зачем:** на целевой Pi 3 скопировать папку куда угодно (например `~/Raspberry_Pi_3_HomePortable`), включить автозапуск Docker и выполнить `docker compose up -d`: поднимутся два контейнера с **`restart: unless-stopped`** — **Home Assistant** и **HomeKit‑мост** (HAP-python + `lgpio`): **гаражные ворота** (тип Garage Door в «Дом») через импульсы на **CH1/CH2** и **ещё шесть** обычных выключателей на **CH3…CH8** Waveshare RPi Relay Board B. Константы в `switch/app/config.py`: `BRIDGE_DISPLAY_NAME`, `GARAGE_*`, `SWITCH_CHANNELS`. Концевики ворот в этой сборке не используются — состояние «открыто/закрыто» в Home синтетическое (после команды и импульса).
- **Ограничение Pi 3:** у Switch проброшен **только** `/dev/gpiochip0` (на Pi 3 **нет** `gpiochip4` на гребёнке — не добавлять).
- **НЕ путать** с конфигурацией **Raspberry Pi 5** в основном дереве проектов: там Switch использует `Проекты/Apple HomeKit accessory/Switch/docker-compose.yml` **с двумя** gpiochip. Эта папка — **изолированный сценарий только для Pi 3** и офлайн‑переноса.
- **Дубль кода:** `switch/` — копия логики из `Проекты/Apple HomeKit accessory/Switch/`; изменения живут там, потом при необходимости **ручным** слиянием перенести сюда (см. конец файла).

Если задача пользователя связана именно с **переносом на другую малину** или со **стартапом только из этой директории** — считать **активным** этот каталог **`Raspberry_Pi_3_HomePortable`**. Техсправочники по платам — в базе **`Платы и модули/`** (`Raspberry_Pi_3_Model_B`, `RPi_Relay_Board_B`).

---

Самодостаточная папка на практике: **скопируйте на Raspberry Pi 3** (USB, `rsync`, `scp`, архив) и поднимите контейнеры. Пути **относительные**.

| `scripts/bootstrap_pi3_docker.sh` | на целевой Pi 3 (**один раз, от root**): `docker.io` + **`docker-compose`** (пакет Debian **trixie**, даёт `docker compose`), **`sync_hap_bind_from_lan.sh`**, `docker compose build` + **`up -d`** |

| `scripts/sync_homekit_bridge_advertise_ip.py` | синхронизирует `ha_config/.storage/core.config_entries`: для `homekit` задаёт `ip_address=0.0.0.0` и `advertise_ip` = `HAP_BIND_ADDRESS` |

| `scripts/ufw_allow_homekit.sh` | если **ufw active** — **allow** TCP **51826**, **21064**, **21065** (мост «Гараж» и типичные порты HA HomeKit Bridge); запуск: **`sudo bash`** |

## Перенос на малину 3

**Вариант A — один скрипт (после копирования папки на Pi 3):**

```bash
cd ~/Raspberry_Pi_3_HomePortable
sudo bash scripts/bootstrap_pi3_docker.sh
```

**Вариант B — вручную:**

1. На **целевой** Pi установите Docker и Compose (**в Debian 13 / trixie** пакет плагина — **`docker-compose`**, не `docker-compose-plugin`):

```bash
sudo apt update && sudo apt install -y docker.io docker-compose
sudo systemctl enable docker --now
sudo usermod -aG docker "$USER"
# перелогиньтесь, если добавляли группу docker — либо вызывайте docker через sudo до перелогина
```

2. Скопируйте **всю папку** `Raspberry_Pi_3_HomePortable` на Pi, например в `~/Raspberry_Pi_3_HomePortable`.  
   **Не используйте** `rsync --delete` с хоста-разработки на уже запущенный узел без исключений: иначе можно затереть **`ha_config/.storage`** и базу HA.

3. В каталоге проекта:

```bash
cd ~/Raspberry_Pi_3_HomePortable
cp .env.example .env
bash scripts/sync_hap_bind_from_lan.sh
# при необходимости поправьте TZ и HOME_ASSISTANT_TAG в .env;
# при активном ufw: sudo bash scripts/ufw_allow_homekit.sh
docker compose build
docker compose up -d
```

После `up` проверьте: `docker compose logs switch | head -n 20` — строка **`HomeKit: advertised_address=`** должна совпадать с IPv4 малины в вашей Wi‑Fi (тот же, что видит iPhone).

При **копировании проекта с ПК на другую малину** не переносите чужой **`.env`**: на целевой Pi снова **`bash scripts/sync_hap_bind_from_lan.sh`** (или **`bash scripts/sync_hap_bind_from_lan.sh --force`** после смены сети).

После смены Wi‑Fi на этой же Pi используйте:

```bash
cd ~/Raspberry_Pi_3_HomePortable
bash scripts/sync_network_identity.sh
```

Для полностью автоматического режима можно повесить этот скрипт на NetworkManager dispatcher (`/etc/NetworkManager/dispatcher.d/`).

### Удаление Tailscale с малины (если ставили вручную)

Если Tailscale больше не нужен (доступ только по LAN), на **самой Raspberry Pi** выполните:

```bash
cd ~/Raspberry_Pi_3_HomePortable
sudo bash scripts/remove_tailscale.sh
bash scripts/sync_hap_bind_from_lan.sh --force
bash scripts/sync_network_identity.sh
```

После этого в **`hostname -I`** не должно оставаться **`100.x`**; HomeKit снова будет ориентироваться на обычный Wi‑Fi IPv4.

4. Проверка:

```bash
docker ps --filter name=homeassistant --filter name=switch
```

После перезагрузки Pi контейнеры снова поднимутся (**`restart: unless-stopped`** + включённый **`docker`**).

## Переезд с уже настроенным Home Assistant

Скопируйте с **старой** машины содержимое каталога конфигурации HA (как минимум `.storage`, ваши `yaml`, кастомизации) **в** `./ha_config/` вместо минимального набора, сохранив актуальность `configuration.yaml` на целевой системе. Конфликты версий образа учитывайте вручную.

## HomeKit

- В приложении «Дом» добавляется **мост** с именем из `BRIDGE_DISPLAY_NAME` по умолчанию **«Гараж»**; под ним **«Ворота»** (управление открыть/закрыть) и **шесть** переключателей (имена в `SWITCH_CHANNELS`).
- После смены типов аксессуаров (8 выключателей → ворота + выключатели) рекомендуется **сброс pairing** (`./scripts/reset_homekit.sh`) и повторное добавление моста.
- PIN и код сопряжения: `switch/app/config.py`.
- Состояние pairing: `switch/app/switch.state`.

```bash
./scripts/reset_homekit.sh
```

### Кнопка сброса pairing прямо в Home Assistant

В `ha_config/configuration.yaml` добавлена кнопка `Сброс спаривания HomeKit (Pi3)` (entity `button.pi3_homekit_reset_button`).

Что делает кнопка:

1. Запускает `/config/reset_homekit_pairing.sh`.
2. Очищает HomeKit-записи HA (`homekit/homekit_controller`) и файлы `homekit.*.{state,aids,iids}` в `/config/.storage`.
3. Удаляет `/switch_app/switch.state` (для этого в `docker-compose.yml` у `homeassistant` смонтирован `./switch/app:/switch_app`).
4. Перезапускает контейнер `switch` автоматически через Docker API (`/var/run/docker.sock`).
5. Перезапускает контейнер Home Assistant.

### Ошибка `switch.turn_on` и UUID вроде `00000025…` после смены моста (ворота + выключатели)

Иногда в **Home Assistant** остаются старые сущности **`switch.*`**, указывающие на HAP‑аксессуар, где теперь **GarageDoorOpener**. Тогда HA шлёт характеристику **«On»** (`…0025…`), её у «ворот» уже нет — в логе **`KeyError`**. После нашего обновления **«Ворота»** в HA должны быть в домене **`cover`**, не **`switch`**.

Сброс **только** интеграции HomeKit Controller и её реестров (резервная копия `ha_config/.storage_backup_homekit_reset_*`):

```bash
cd ~/Raspberry_Pi_3_HomePortable
docker cp scripts/reset_ha_homekit_controller_storage.py homeassistant:/tmp/reset_ha_hk.py
docker compose exec -T homeassistant python3 /tmp/reset_ha_hk.py
docker compose restart homeassistant
```

Затем в HA снова добавьте мост **HomeKit Controller**, код из `switch/app/config.py` (по умолчанию **`123-45-678`**). Для ворот используйте **`cover.open_cover`** / **`cover.close_cover`**.

### На iPhone после добавления моста не видно ворота и выключателей

1. Откройте **Дом** → нужная комната (или **Комната по умолчанию**) — под плиткой моста **«Гараж»** обычно отдельным рядом идут **Ворота** и каждый **Выключатель**; прокрутите экран ниже заголовка комнаты.  
2. Либо **Дом → … (или Дом)** → **Параметры дома** → **Мосты** / **Подключённые мосты** → выберите **Гараж** — там показано число объектов через мост.  
3. Если отображался только один мост без объектов — обновление проекта выставляет **уникальный SerialNumber** для моста, ворот и каждого реле (ранее у всех стояло `default`, из‑за чего приложение «Дом» может не показать череду устройств). После **`docker compose up -d --build`** удалите старый мост в **Дом** и добавьте его снова по коду (**`123-45-678`** или из `config.py`), либо дождитесь обновления каталога (версия конфигурации в mDNS может подняться автоматически).

### В одном доме приложения «Дом» работает мост, в другом только «видится», особенно в Wi‑Fi ELEKTRO_

Один физический мост HomeKit можно **полноценно спарить только с одним домом Apple** (одна запись pairing на аксессуар). Если вы сначала добавили мост в дом **«Работа»**, повторное «добавление» в **«Дом»** может пройти по шагам мастера, но **управление не будет стабильным** без **удаления моста из первого дома** и **`./scripts/reset_homekit.sh`** перед привязкой ко второму.

Отдельно на конкретных роутерах (в том числе в ELEKTRO_):

1. В доме **«Дом»** часто уже назначен **концентратор дома** (Apple TV или HomePod). Команды с плиток могут идти **через концентратор**. Если между концентратором и Raspberry Pi включена **изоляция клиентов Wi‑Fi**, **guest SSID**, **разные VLAN** без маршрута к малине или фильтры **mDNS** — в этом доме будет **«нет ответа»**, пока телефон в другом доме без концентратора ходит **напрямую по LAN** и всё работает.
2. Проверка: **«Дом» → Параметры дома для … → Концентратор дома / Резервирование»** — временно выберите этот телефон как концентратор (**только для проверки**) или отключите концентратор **только** для проверки; если управление после этого начинает доходить, причина в **доступности Pi с концентратора**, а не в коде малины.

После любых экспериментов с двумя домами: удалите лишний мост во **всех** домах где он отображался, выполните сброс (`./scripts/reset_homekit.sh` и при необходимости блок про HomeKit Controller в этом README), оставьте мост только в том доме, которым будете пользоваться постоянно, и заново добавьте **Home Kit Bridge** HA при вашем сценарии через HA.

### Прямой мост «Гараж» в «Дом» не переключает ворота и выключатели (из HA всё ок)

Частая причина: в **Bonjour** для HomeKit объявляется **не тот IPv4** — например первым в `hostname -I` стоял другой интерфейс или **Tailscale** (`100.x.x.x`). Скрипт **`sync_hap_bind_from_lan.sh`** подставляет **`HAP_BIND_ADDRESS`**, в том числе по **`src` маршрута по умолчанию**, чтобы малина рекламировала **тот же IPv4**, что использует активный Wi‑Fi/LAN для выхода в сеть. Если поведение сменится после **`bash scripts/sync_hap_bind_from_lan.sh --force`** и перезапуска **`docker compose up -d`** — см. журнал **`docker compose logs switch | head`**, строка **`HomeKit: advertised_address=`**.

Что сделать:

1. После рестарта контейнера посмотрите лог: `docker compose logs switch | head -n 30` — должна быть строка **`HomeKit: advertised_address=…`**. Это адрес, который увидит iPhone для TCP.
2. В **`.env`** в корне проекта задайте **`HAP_BIND_ADDRESS=<IPv4 малины в вашей Wi‑Fi/LAN>`** (тот же адрес, что и в настройках роутера / `ip -4 addr` для `wlan0` или `eth0`). Затем **`docker compose up -d`**.
3. Удалите мост **«Гараж»** из «Дом», выполните при необходимости **`./scripts/reset_homekit.sh`**, заново добавьте мост по PIN из `config.py`.
4. Проверьте **ufw**: должен быть разрешён **входящий TCP 51826** с подсети Wi‑Fi (если фаервол включён).

### После добавления моста «Гараж» в HA телефон больше не видит «Гараж» в «Дом»

Один и тот же мост HomeKit на контейнере **`switch`** нельзя «раздать» двум независимым контроллерам Apple и Home Assistant так, чтобы **и** iPhone оставался сопряжён **напрямую** с «Гаражом», **и** Home Assistant одновременно держал **HomeKit Device** к этому же мосту. Когда в HA завершается сопряжение **HomeKit Device** (контроллер) с кодом из `config.py`, на аксессуаре фиксируется сопряжение с **HA**; прежнее сопряжение с приложением **«Дом»** перестаёт работать — мост исчезает из обнаружения или показывается как недоступный. Это не сбой сети, а смена «владельца» сопряжения по протоколу HomeKit.

Что делать:

| Цель | Действие |
|------|-----------|
| Нужны **и** сценарии в **HA**, **и** управление в **«Дом»** на телефоне | Оставьте **HomeKit Device** в HA к **«Гараж»**. В **«Дом»** **не** восстанавливайте прямой мост «Гараж». Добавьте в «Дом» только **Home Kit Bridge** из HA (экспорт ваших `cover.*` / `switch.*`). Телефон управляет через мост HA; см. выше раздел про **advertise IP** и порт/firewall. |
| Нужен только **телефон** к «Гараж», **HA** через HomeKit к малине не нужен | В HA **удалите** интеграцию **HomeKit Device** к «Гараж». Выполните **`./scripts/reset_homekit.sh`**, перезапустите **`switch`**. Снова добавьте в **«Дом»** мост **«Гараж»** по PIN из `config.py`. |

### Ни в приложении «Дом», ни в Home Assistant после передобавления ничего не видно

1. **Порт HomeKit должен слушать все интерфейсы (`0.0.0.0`).** Ранее сокет был только на LAN‑IP — с **той же** Pi **Home Assistant** (`network_mode: host`) не достукивался до **`127.0.0.1:51826`**. В коде: **`listen_address="0.0.0.0"`** и **`advertised_address=<IPv4 LAN>`** (`hostname -I` или **`HAP_BIND_ADDRESS`**).
2. **Сброс pairing моста:** `./scripts/reset_homekit.sh`, затем при смене кода контейнера — `docker compose up -d --build switch`. Снова добавьте мост в **«Дом»** по PIN из `switch/app/config.py`.
3. **В HA интеграцию нужно добавить вручную:** Настройки → Устройства и службы → Добавить интеграцию → сценарий **подключения HomeKit‑аксессуара** (в англ. UI часто **HomeKit Device**). Тот же PIN. Без этой записи в `config_entries` в HA **не будет** сущностей.

### Плитки через HASS Bridge на iPhone есть, а управление с телефона не срабатывает (из HA всё работает)

Цепочка команд: **телефон → интеграция Home Kit Bridge в HA → сущности (`cover` / `switch`) → HomeKit Controller → мост «Гараж» на `switch` (51826)**. Плитки видны потому, что сопряжение с экспортирующим мостом HA уже есть; если **команды записи** не доходят или не обрабатываются, симптом будет именно такой.

Что проверить по порядку:

1. **Журнал HA** при нажатии плитки в «Дом»: *Настройки → Система → Журналы*, поиск по `homekit`. Ошибки вызова сервисов к `cover.*` / `switch.*` или к **HomeKit Controller** покажут обрыв на конкретном шаге.
2. **Сеть:** iPhone в том же **LAN**, что и Pi (или маршрут до **LAN‑IP малины** открыт). TCP к порту **Home Kit Bridge** (в карточке интеграции **Home Kit Bridge**, часто **21064**) не должен блокироваться (например **ufw** на Pi — разрешить с подсети Wi‑Fi).
3. **Рекламируемый IP:** в настройках интеграции **Home Kit Bridge** укажите **объявляемый / advertise** адрес = **статический IPv4 малины в домашней сети**, с которой ходит телефон. Иначе после обнаружения mDNS клиент может стучаться не туда (особенно при нескольких интерфейсах, VPN, Tailscale).
4. **Прямой мост «Гараж» на телефоне и HomeKit Device в HA к тому же мосту совместить нельзя** (см. раздел выше «После добавления моста «Гараж» в HA…»). Если в HA уже есть **HomeKit Device** к «Гараж», в «Дом» на телефоне используйте **только Home Kit Bridge** из HA. Вариант «удалить HASS Bridge и управлять напрямую Гаражом» подходит **только** если вы убрали HomeKit Controller к «Гараж» из HA и сбросили pairing на малине.

### В «Дом» везде «Нет ответа», хотя мост HASS Bridge добавлен

Интеграция **Home Kit Bridge** в HA **не создаёт** ворота и реле сама — она только **прокидывает в Apple уже существующие сущности HA** (`cover.*`, `switch.*` и т.д.). Если в HA **ещё не добавлен** поток **«Устройство HomeKit»** (контроллер) к мосту «Гараж» на порту **51826** по PIN из `config.py`, в реестре **нет** `cover.*` / `switch.*` с малины — плитки в «Дом», ушедшие через HASS Bridge, будут **без ответа**. Порядок: сначала **HomeKit Device** в HA (или управление только прямым мостом «Гараж» в «Дом», без дублирующего HASS Bridge), затем при необходимости настройте **Home Kit Bridge** в режиме **include** только для появившихся сущностей.

- После включения малины LOW-active реле могут кратко или до старта Docker быть во «включенном» виде без вашего управления; в коде включаются явный **`relay_off()`** после захвата GPIO и по умолчанию **`FORCE_ALL_RELAYS_SAFE_OFF_AFTER_LOAD`** в **`switch/app/config.py`** — после загрузки `switch.state` все каналы переводятся в «выкл» на плате и в HomeKit (безопасный старт; при необходимости восстановления предыдущих состояний — поставить константу в `False`, не рекомендуется для ворот/нагрузок).

## Память Pi 3 (1 ГБ)

Home Assistant может потреблять много RAM — при нехватке упростите интеграции или вынесите HA на другую систему, оставив в этом проекте только `switch` (тогда отредактируйте `docker-compose.yml` и уберите сервис `homeassistant` или закомментируйте).

## Синхронизация с основным репозиторием

Каталог `switch/app` **развивается отдельно** от одиночного `Проекты/Apple HomeKit accessory/Switch/`: здесь **мост «Гараж»** (ворота + 6 выключателей) под плату реле. Основной репозиторий Switch синхронизируйте вручную только если осознанно переносите общие изменения (`main.py`/драйвер HAP и т.д.).
